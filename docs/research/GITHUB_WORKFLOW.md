# GitHub 研究工作流

仓库：[shuo19mo/prediciton-token](https://github.com/shuo19mo/prediciton-token)。GitHub Issues/Milestones 是唯一动态进度入口；Git 保存详细研究产物及演变。[STATUS](../STATUS.md) 只做导航，`configs/work_queue.json` 只映射 R 阶段。

## 当前路线与角色

当前协议和执行范围见 [issue #15](https://github.com/shuo19mo/prediciton-token/issues/15)；[#14 验收评论](https://github.com/shuo19mo/prediciton-token/issues/14#issuecomment-5901809512)只代表数据准入通过。

#15 的分工是：Astra 规划并独立验收；Luna 检查返回接口并独立评价；师兄确认协议和受控数据范围，负责实现、训练和调参；主代理管理工作区与 GitHub。不得代替他人确认，也不得未经明确授权联系师兄。

同一时刻只执行一个 issue。当前 issue 正等待师兄训练时，可在同一 issue 范围内继续不依赖训练的接口检查或评价准备；不提前启动下一项。

当前 issue 的规格应足以交给指定执行者，至少包含问题及重要性、证据与来源、待验证假设、工作步骤、负责人及依赖、交付物、验收标准、反证条件，以及状态/结论/证据位置。还应列清输入文件和版本、可复用实现、工作边界、输出契约、错误和未知的处理、运行方式及需返回的材料。普通实现细节由执行者决定；证据不足的科学决定保持开放。规格纳入 Git 并链接到 issue，任务状态只记在 GitHub。

缺少本地数据或依赖时，应准确列出缺失项。只运行合成测试不能称为真实数据验收。

执行者交回代码、产物、检查和证据后，由研究负责人复核并记录验收。执行者不得通过自行关闭 issue、自动合并或使用 `Closes #...` 绕过验收。真实验收前保持 issue 开放。负面结果也可完成一项调查，但不会自动通过 milestone。

## Milestone 与 issue

Milestone 说明研究问题、进入条件、交付物、证据门槛和重构条件。只为当前阶段建立实际需要的 issue。验收后依据新证据决定一个必要的下一步，再创建该 issue；不提前建立未来实验任务。blocked、needs-training、in-progress 标签和 open/closed 生命周期须反映真实状态。若任务等待师兄训练，应保留该依赖，不得虚构确认或结果。

开始执行 issue 时，只有确认依赖已经满足才移除 `blocked`，并按实际情况添加 `in-progress`、评论本轮范围和证据。发现来源、结论或方向变化时，在 issue 留下版本、结论及影响。完成时记录验收、限制与固定 Git 提交链接，再由研究负责人决定是否关闭；验收前不启动下一项。

2026-09-28 的七个 milestone、十个 issue 初始化，以及之后的路线调整，都是历史配置记录，不是可以重放的操作指令，也不是当前对象数量或状态快照。不要重跑 bootstrap/replan 配置；应读取当前 [#15](https://github.com/shuo19mo/prediciton-token/issues/15)、milestone 和评论。#9 是历史停止证据调查，不是当前 issue。

## Git、数据与公开

只发布逐份审查过的研究管理文件及安全工具/报告。原始记录、调用正文、参考答案、逐题真值和用量、测试标签、受控训练/评价包、凭据及第三方缓存均不提交。固定来源保留 URL、revision 和 SHA-256。公开聚合报告按当前协议抑制小样本单元。文件的本地路径不代表其公开可访问。

正式实验前固定数据、代码和协议版本、同题分组、输入白名单、选优规则及测试查看记录。记录既有 SAB 开发暴露，不得称受其影响的数据为完全未查看。训练进程不得访问评价真值；目录名本身不是隔离证据。正式测试发生任何变更时，登记探索版本和变更理由。

公开 `main` 仅保存逐份审查过的研究管理产物。本地 `codex/local-research-history` 分支保留历史实现与研究版本，不推送该分支，也不用 `push --all`。GitHub 仍是唯一任务状态入口。新增公开历史文件前逐份审查并确认在授权范围内。

旧工作流笔记中关于初始化权限、临时 `GITHUB_TOKEN` 和旧自动化的说明只记录已完成设置，不授权新建凭据、扩大权限、对外联络、购买、投稿或重跑设置流程。
