## 三个可评价候选

### A — 最终成功的一次运行，其观测 token 终点

- **单位与条件：** 一条 benchmark 运行 `r`，绑定任务 `x` 和冻结的既有 agent 配置 `a`；仅对按原 benchmark evaluator 判定最终成功的运行定义标签 `U_r`。
- **目标量/群体：** 单条成功运行从原始运行开始到该成功运行记录终点的 actor token 用量。若训练/测试需要群体泛化，明确目标是同任务、同配置生成机制下 `S_r=1` 的运行条件群体中的预测误差；单条 `U_r` 是观测标签，群体条件均值或中位数是可另行选择的统计量，不能将二者混称。
- **预测时点、接收方与用途：** 运行开始前，把合法任务信息与已有配置信息交给预算规划者/实验者，估计一条尝试若最终成功会消耗多少 token，用于成功尝试的条件资源规划，或在独立成功质量已可接受时比较配置的成功成本。它不能单独决定是否启动任务，因为不预测成功概率；也不承诺能让运行成功。条件成功群体对运行前个体的实际决策价值尚待论证。
- **成功的角色：** `S=1` 用来定义目标标签和目标评价群体；它不得作为运行前输入。要在未来部署中只对未知是否成功的任务预测，目标群体如何从运行前可见资料定义仍需另行讨论，不能将未来成功标记泄漏给预测器。
- **已知事实与假设：** 成功运行的终点 token 在原则上可直接观察；M0 汇总存在 161 个合格成功终点/81 个任务身份。候选假设同一条日志能对齐任务、配置、token 角色及 evaluator 成功事实，而且所需输入在运行前已存在。当前没有 M2 支持度检查，不能说这些字段已足够。
- **用途失败/证伪：** 如果日志无法一致地给出 actor token、成功标签或运行前关联字段，目标不能评价；若只能靠成功筛选得到极少/严重混杂的任务×配置组，则不具备所需群体支持。即使可评价，若它只是 TokenCast 一般终止消费任务的常规成功过滤，且这个过滤不回答重要的独立决策问题，则应判 `OVERLAP_NO_CLAIM`，不以换标签/换数据维持贡献。

### B — 同任务、同配置的成功运行成本分布或代表统计量

- **单位与条件：** 固定任务 `x`、配置 `a` 与运行随机机制；样本是不同成功运行 `r`，而非把重试拼成一条轨迹。
- **目标量/群体：** 成功运行条件分布 `F(U | x,a,S=1)`，或从它预先指定的代表量，例如总体均值 `E[U | x,a,S=1]`、中位数。总体均值/中位数是跨该条件群体的 estimand；有限个成功重复运行的样本均值/中位数只是估计统计量，二者不是同一个目标。现有材料没有证明每个 task×agent 条件有足够、可交换的重复成功运行来支持该目标。
- **预测时点、接收方与用途：** 运行前给固定任务和配置的规划者预测成功条件下的典型/期望资源需求，服务于跨任务/配置的成功成本规划；若用途仅是预测某条具体运行，则聚合量与决策需求不匹配。
- **成功的角色：** `S=1` 定义目标分布与评价样本，不作为运行前特征。这里的条件化与输入泄漏无关；只有把未来运行结果、实际 token 或成功判定放入特征才泄漏。
- **已知事实与假设：** D01 有四次独立运行且代码将四次 usage 固定除以 4 形成聚合值，但实际 ground-truth CSV、行生成链及其上游成功筛选未知；不能把 D01 四次均值说成 B，也不能断言其均值输入造成泄漏。B 还要求规定统计量、群体机制及足够的重复支持。
- **用途失败/证伪：** 无重复/可比成功运行则总体分布与代表值不能从现有记录支持；若一个 task×agent 只有一个成功样本，不能把观察值称为已识别总体均值。即便估得某统计量，若它只是对已有每次终止消费预测再做普通聚合且不带来独立重要用途，不构成贡献候选。

### C — 同一原始运行规则继续到成功的潜在 token 成本

- **单位与条件：** 一条原始运行路径 `r`，在同一任务、agent/scaffold、初始状态、工具/环境、提示和策略规则下，从真实起点延续。`T_r^success` 是按原 evaluator 第一次判为成功时的累计 actor tokens。
- **目标量/群体：** 若运行在 `U_r` 被行政性截断，目标是同一条未被中断路径本会到达首次成功时的 token 数；其条件群体必须明确（例如原规则最终能成功的路径），不能将“最终可成功”默认为所有失败都满足。起始后重置/独立重试不是同一条潜在路径，不允许拼接成“继续到成功”。
- **预测时点、接收方与用途：** 运行前为资源计划者预测在原规则不被外部截断时、同一尝试到达首次成功所需资源。
- **成功的角色：** 反事实成功定义目标终点；实际最终成功、完整前缀首次成功、行政停止及停止时间的可观测关系是识别问题。成功状态与未来终点不进入预测输入。
- **已知事实与假设：** 需要同路径可延续、`T>U`、终止原因确属外部截断、首次成功可见，以及可辩护的删失机制等。M0 四项判断全部 unknown，训练获准行数 0；自然失败不能按已知右删失处理。
- **用途失败/证伪：** 若自然失败改变路径/策略、停止为吸收性失败、没有同规则可延续证据、或记录看不到首次成功，则潜在成本不由这些日志识别。不能用独立 rerun、最终成功标签或事后插补补造反事实。当前不保留 C 为候选，也不提出 survival 方法。

## 最强反例及候选判断

**最强反例：TokenCast 加上 D01 的自估/聚合结果。** TokenCast 已明确覆盖运行前、task-level 的实际终止消费预测，含同一任务重复运行、task-group split 和 Self-Prediction/history baseline；D01 已展示执行前自估和多运行均值。最有力的反对解释是：对于一个计划成功完成的尝试，直接用一般 run-consumption predictor，再在训练/评价中只保留成功运行，可能已经得到 A；对 B 可进一步做常规分组聚合。成功筛选本身是目标定义的改变，但不自动带来科学重要性或审稿人可辨认的增量。

对此只能作有限回应：近作论文直接定义的预测对象是通常终止/记录到的消费；它们没有在固定公开证据中明确建立“同一 agent 条件下只预测成功运行 endpoint”的目标及其评价用途。但实现训练行筛选的 unknown 不应被当作不存在该做法的证据，也无需无限等待代码公开。条件成功成本只有在资源规划/配置比较中回答了一个不可由现有一般消费预测加简单筛选解决的重要问题，才可能成为有意义差异；本报告尚未证明这个前提。故当前最稳妥的判断是：A 是一个容易被既有方法解决的可观察候选，只值得一次支持度和字段检查；尚无依据主张它构成独立贡献。若近作加普通成功过滤已足够，或者该条件群体没有独立决策价值，A 应撤销。B 的总体分布/代表值更依赖重复成功支持且被 D01 均值强烈邻接。C 的必要机制目前不具证据资格。

## 翻转条件与阶段边界

- **A 从暂留翻为 `NO_SUPPORTED_CANDIDATE`：** M2 发现成功 endpoint、运行前特征或 task×agent 同源分组缺失/不一致，无法定义诚实评价；或其唯一价值只是同类实际终止成本预测的常规成功过滤，不存在值得研究的决策差异。若 TokenCast/D01 后续固定证据明确显示同一成功条件目标、输入时点和评价用途已被比较，本候选也应撤销，而不是改名维持。
- **A 的暂留不能翻译为 `GAP_SURVIVES` 的实证结果：** 需后续论证成功条件估计带来的决策差异重要、与近作真正不同且可证伪；再由 M2 确认可评价群体与支持。未来预测效果、跨划分稳定性不是当前 M1 的“保留”含义；如果 M3/M4 结果只追平有同等输入的强基线，应收回贡献。
- **B 可重新进入讨论的条件：** 有可审计的重复成功运行机制、足够的 task×configuration 支持，且先规定所指总体与统计量；有限样本均值不得冒充总体 estimand。它不是本次推荐。
- **C 可重开条件：** 固定现有路径和记录证明候选行确属外部停止，并满足同一延续规则、首次成功可见及删失识别条件。四项未知没有满足前，不将 C 交给训练。
- **有限停止规则：** 若 M2 一次字段/支持检查不能为 A 建立成功终点、合法运行前输入和可分组评价样本，就记录具体缺口并停止将 A 作为现有数据候选；不等待未来作者代码、不补采、不拼重试、不训练。若 M2 的结果只能支持“成功子集上的一次运行条件预测”，也只把主张限定到该群体，不推及所有任务或潜在成本。
